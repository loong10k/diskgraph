# Desktop read-only production readiness — 2026-10-02

> Historical gate: this record covers the desktop read-only subset at `3d831bc3`. The full-platform expansion and subsequently reproduced FFI/MCP contract defects are tracked in the [current implementation record](production-readiness-full-platform-2026-10-02.md). This table does not certify the latest source for all platforms.

The **native code and artifact gate passes** for the read-only CLI and MCP stdio, Streamable HTTP, and legacy SSE on macOS arm64/x86_64, Linux x86_64, and Windows x86_64. These binaries are candidates for a controlled production deployment. They have not been signed, published, or exercised against a production data directory. File mutation tools remain disabled; Windows content reads remain unsupported. OpenSpec `implement-diskgraph-platform` RE-06 and Q-09 define this scoped gate.

[CI run 36913827691](https://github.com/loong10k/diskgraph/actions/runs/36913827691) passed all 13 jobs at source commit `3d831bc3f467d9bbfb54d4cba5a17a0cb67444a2`: rustfmt, vendored scanner verification, stable and Rust 1.97 workspace matrices, and four native release-profile package jobs. Each extracted package passed real-binary stdio 11/11, authenticated HTTP/SSE 13/13, isolated upgrade/rollback 7/7, and a 20k-file concurrent load drill 4/4. The protocol tests use valid signed tokens, database grants and isolated directories; they reject anonymous, ungranted, revoked, and hostile-Origin requests. The Windows drill also refuses a verifier key readable by `Everyone`. The package script checks that extracted binary digests equal the built binaries. All four packages report `diskgraph 0.3.0`; all four load drills published the full revision, kept concurrent reads on that revision, bounded responses, and refused partial publication when the node budget was exceeded. These are individual CI runner observations, not an SLA or a controlled comparison of OS speed. Windows cold CLI startup is currently material at p95 2.85 seconds under four clients; a latency-sensitive deployment needs an explicit target-host SLO and measurement. Per-platform peak RSS was not captured by this drill.

The separate [local release benchmark](benchmarks/readiness-2026-10-02.json) uses macOS arm64 isolated fixtures with 32-byte files. Positive-target candidate query p95 improved from 12.38 ms for a full revision load to 0.35 ms for a narrow read at 20k files, and from 106.04 ms to 0.36 ms at 200k files. These are warm-cache samples (3 full-load and 11 narrow-read calls), not an SLO. Scan-phase peak RSS was approximately 37 MB at 20k and 225 MB at 200k; database files were approximately 31 MB and 316 MB. The scanner has no strict RSS ceiling. Local `RUSTFLAGS='-D warnings' cargo test --workspace --all-targets --locked --no-fail-fast --quiet`, workspace Clippy with `-D warnings`, explicit workspace-crate fmt, vendored digest verification, and `cargo audit --json` passed; the audit reported zero vulnerable dependencies.

Schema 8 adds candidate-size and evidence-relation indexes. Upgrades create a SQLite-consistent pre-upgrade backup of the graph and control databases under `migration_backups/`; the v7→v8 fixture verifies preserved committed data and both indexes. Each native package job builds an older schema-4 CLI in isolation and performs the 7-check extracted-binary upgrade/rollback drill. For operational rollback, stop CLI/MCP and job workers, retain the failed upgraded data directory, restore **both** databases from the same pre-upgrade backup set, then start the previous binary against that restored directory. Do not open a newer schema with an older binary. Graph WAL/NORMAL may lose recent rebuildable index commits on power loss; control FULL protects its own transactions, and the two databases have no cross-database atomicity.

To reproduce the native package gate, run `python scripts/accept-readonly-package.py --target TARGET --bin-dir RELEASE_BIN_DIR --old-cli OLD_CLI` in an isolated checkout after building current and old binaries. For protocol-only checks, run `python scripts/accept-readonly-stdio.py` and `python scripts/accept-readonly-http.py`, setting `DISKGRAPH_ACCEPT_BIN_DIR` to the binaries under test. The scripts create temporary control/graph databases and never use production data. The listener reads its verifier key from a protected file, and the shipped systemd unit does not put it in process arguments.

The remaining boundary is operational: no signed public release or production-host soak has occurred; native CI does not replace site-specific backup, capacity, latency, and monitoring checks. Linux arm64 has a cross-build workflow but no arm64 Linux native acceptance in this CI run. Real-host file-operation drills remain outside regular CI. Windows content reads and all file mutation operations are unsupported in this scope and must remain disabled. The upstream scanner cancellation can overshoot a budget at directory boundaries, so strict peak-memory enforcement is not claimed. The broader OpenSpec item 13.6 remains open for exact wide-directory statistics, historical-comparison workload observation, and TUI page-sort presentation; these are not included in the scoped package gate.
