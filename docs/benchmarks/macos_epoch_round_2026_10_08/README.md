# macOS 协议轮安装核验候选

原实现每个解码检查点都会重新获取安装锁、打开祖先、核验ACL及读取活跃配置。本候选每轮driver poll前核验一次，并以按值检查器持有共享锁覆盖有界协议观察；原业务检查点逐次执行，轮间退避不持锁。更新者沿原协议持同一排他锁，不缓存跨轮授权。

独立代码与架构复核发现初版共享锁覆盖driver内部cleanup，形成阻塞。已修正：poll保存catch结果后先销毁检查器，再进入原错误/panic清理；runtime的move闭包拥有安装锁，原业务回调只重借用。两路复核确认静态阻塞解除。

新增真实子进程回归在错误与panic两种路径核对：测试专用线程本地见证在真实cleanup入口断言检查器资源已释放，返回后原子进程已reap，原错误/panic保留。不使用PID存在性推断清理顺序。它需要root部署的独立原生夹具，本机未安装，因此不能声称该回归运行通过或已取得行为红灯。原driver测试1通过、11项因夹具缺失失败，记录为验收环境不足。

本地实际通过：安装锁8、宿主准入3、CLI启动9测试；engine/CLI all-targets严格Clippy、格式和OpenSpec校验。CLI新增固定启动失败阶段标签，不输出路径或凭据，不改变原错误。

仍需当前候选原生CI的driver生命周期回归、安装更新竞争及macOS200k负载结果；没有性能改善百分比或生产就绪声明。
