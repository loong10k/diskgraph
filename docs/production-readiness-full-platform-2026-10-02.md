# Full-platform readiness implementation record — 2026-10-02

**The full-platform gate is incomplete.** OpenSpec `implement-diskgraph-platform`, section 15 and RE-07, is the source of truth. The earlier desktop read-only gate does not certify mobile providers, native hosts, platform file operations or distribution. Dangerous CLI/MCP file tools remain disabled. Nothing has been published or connected to production data.

Implemented with isolated regressions: actual MCP input schemas, explicit revision/non-root node queries and unknown-argument rejection; stable bidirectional relation pagination with entity/evidence/cursor byte checks before decoding; failed content verification charged to attempt and actual byte budgets; per-chunk Ops authorization/approval/deadline/cancellation checks, approved source versions bound to atomic publication, and immutable terminal states; persistent FFI services, real scan progress, shared handles, shutdown cancellation and result revisions fixed to job/fence. Individual grant revocation prevents running and completed handles returning cached data. Engine scope listing and its admin fallback also check live grants. Trusted internal compatibility without a persisted policy is excluded from remote entry points.

The scanner pin, source and digests are unchanged. Irrecoverable non-Unicode names reject publication to avoid addressing another file through a lossy display name. Valid U+FFFD names cause at most one additional enumeration per parent. The Windows observer reads actual volume/file identity through an attribute handle; a 128-bit ID that cannot fit the existing 64-bit field remains unknown. macOS content/copy operations disable dataless materialization for the current thread and restore its original policy. This local policy test does not certify a real cloud provider or equivalent Linux/Windows protection.

One-shot CLI queries no longer start a background queue. `--wait` verifies the job's terminal state and resolves its exact job/fence revision. It only conditionally reclaims that expired job or settles its cancelled/revoked expired owner; unrelated jobs and live leases remain unchanged. The waiting deadline bounds waiting/admission, while an admitted scan uses its separate Engine budget. Runner Drop checks stop before/after queue reads and before each claim; previously admitted work may complete under its budgets/lease. This is not instantaneous cancellation. SQLite errors preserve extended codes and startup failures include a phase marker. This behavioral increment passed the f57aa40 cross-platform CI above.

Schema 9 materializes exact snapshot counts, directory total/unknown counts and descending size-prefix counts in the publication transaction. Minimum-size counting is an index probe; known-size pages use a matching partial index. Legacy JSON size fallback and unknown-node numeric semantics remain. Regression fixtures with 200k children verify fewer than 1,500 SQLite VM steps rather than 5.1 million for counting and 3.2 million for a known-size page across unknown rows. Explicit offset pagination still costs O(offset + page). MCP children now has a v2 cursor bound to the actual principal, scope/revision, parent, minimum, ordering and current policy epoch; it seeks by size descending/name/ID ascending and preserves explicit offset/next_offset compatibility. Deep 200k same-size and distinct-size pages both use fewer than 1,500 VM steps. Search continuation seeks by name/ID, reducing a fully matching 200k deep page from about 1.6 million to fewer than 2,000 VM steps without changing Rust Unicode lowercase substring semantics. Lookahead only probes existence without converting the extra Rust node/locator fields; byte-shortened pages resume from the actual last item. The children 64 KiB budget covers tool data; JSON-RPC/text/structuredContent wrapping costs are separate.

## Storage structure increment (ST-06 / task 15.7)

The storage entry decreased from 3,247 to 93 lines and now contains only module declarations and stable reexports. Real query, publication, migration and control/execution persistence functions live in responsibility-specific modules; the largest production module is the 410-line job store. Each type has its own source file, with Chinese documentation describing its actual native Rust provenance and parameter/return semantics. This introduces no Java mapping, public repository wrappers or additional connection owners. [The storage README](../crates/diskgraph-store/README.md#source-boundaries--源码边界) and both architecture documents show the resulting boundaries.

The new AST source-layout regression first failed on the old multi-type entry files and wildcard imports, then passed after the split. It also checks Chinese documentation, forbids placeholder documentation and rejects production stubs. Existing tests remain: store all-targets is 76 passed / 5 ignored; workspace is 582 passed / 13 ignored. Workspace Clippy, package-directed fmt, OpenSpec strict and the release CLI/MCP/FFI build passed. Release stdio 18/18, HTTP/SSE 13/13 and four-process load 4/4 passed again. [This run's isolated load data](benchmarks/store-structure-load-2026-10-02.json) records a 0.423-second 20k scan, p50 7.389 ms/p95 11.24 ms for 32 queries and 37,445,632 database/WAL bytes. This structural change claims no measured speedup.

Independent code and architecture review confirmed unchanged public exports, tuple column order, API/wire fields, transaction/fencing/budget behavior and all 185 SQL string occurrences. Review caught and corrected misleading new Chinese descriptions of historical administration grants, trusted state setters, connection/transaction ownership, job quota results and relation-page budgets. Source-layout assertions cannot replace that semantic review. Both reviewers cleared this increment. [The same code SHA 63bc6c7 passed all 22 CI jobs](https://github.com/loong10k/diskgraph/actions/runs/36986111434), including five native packages and both real-language host matrices. ST-06 covers the storage crate and does not certify every other Rust crate's organization or the unfinished full-platform capabilities.

## Connection admission follow-up (MCP-06 / task 15.8)

[The subsequent documentation-only 1ba56aa CI](https://github.com/loong10k/diskgraph/actions/runs/36987130326) passed 21/22 and exposed a Windows TCP reset in the connection-cap test. It did not change the storage implementation; the prior 22/22 run was a successful sample, not proof that this rejection boundary was stable. Extending the existing test to read the complete 503 body reproduced the same reset on macOS before the fix.

Over-cap sockets now receive 503 Service Unavailable with Connection: close, then the server half-closes its write side and discards input with a fixed 4 KiB buffer, a 64 KiB cumulative byte budget and a 50 ms absolute deadline established before sending. No worker, request decoding or Engine call is added. The existing public response writer preserves keep-alive. Oversized or stalled rejected inputs may be terminated at the budget; OS scheduling is not a hard wall-clock limit. Cleanup is synchronous and can briefly pause admission; this makes resources bounded rather than guaranteeing flood fairness or a rejection-throughput SLA.

The complete-body/Content-Length/close regression and two real-socket silent/oversized budget tests pass. Workspace is 584 passed / 13 ignored; Clippy, package-directed fmt, OpenSpec strict and release binaries pass, including stdio 18/18 and HTTP/SSE 13/13. Both independent reviewers approved; a separate reviewer drip probe observed the second rejection after 51.373 ms while the first peer sent bytes every 20 ms. That observation is not an SLA. At this implementation stage, the new source SHA still needs its Windows native CI gate; neither the macOS regressions nor a previous SHA's success proves it.
