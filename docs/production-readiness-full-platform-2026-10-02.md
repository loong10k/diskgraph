# Full-platform readiness implementation record — 2026-10-02

**The full-platform gate is incomplete.** OpenSpec `implement-diskgraph-platform`, section 15 and RE-07, is the source of truth. The earlier desktop read-only gate does not certify mobile providers, native hosts, platform file operations or distribution. Dangerous CLI/MCP file tools remain disabled. Nothing has been published or connected to production data.

Implemented with isolated regressions: actual MCP input schemas, explicit revision/non-root node queries and unknown-argument rejection; stable bidirectional relation pagination with entity/evidence/cursor byte checks before decoding; failed content verification charged to attempt and actual byte budgets; per-chunk Ops authorization/approval/deadline/cancellation checks, approved source versions bound to atomic publication, and immutable terminal states; persistent FFI services, real scan progress, shared handles, shutdown cancellation and result revisions fixed to job/fence. Individual grant revocation prevents running and completed handles returning cached data. Engine scope listing and its admin fallback also check live grants. Trusted internal compatibility without a persisted policy is excluded from remote entry points.

The scanner pin, source and digests are unchanged. Irrecoverable non-Unicode names reject publication to avoid addressing another file through a lossy display name. Valid U+FFFD names cause at most one additional enumeration per parent. The Windows observer reads actual volume/file identity through an attribute handle; a 128-bit ID that cannot fit the existing 64-bit snapshot field remains unknown. Windows content inspection separately keeps the complete native ID in its private handle state. macOS content/copy operations disable dataless materialization for the current thread and restore its original policy. Neither this local policy test nor the Windows thread-exposure and NTFS fixtures certify real cloud-provider no-download behavior; Linux protection remains unfinished.

## Legacy delivery and live authorization (MCP-05/06 / task 15.10)

Remote legacy delivery now uses a private reservation registry. Before acknowledging or executing a tool, it reserves the configured worst-case response plus 22 SSE framing bytes against 64 pending messages/16 MiB per session and 64 MiB per listener. These reservations cover execution, encoding, queueing and partial writes. A full budget returns HTTP 429 before side effects; a single reservation that cannot fit returns 413. The default maximum allows at most three worst-case reservations per session and fifteen per listener. Successful encoding shrinks the reservation to actual UTF-8 wire bytes; queue, in-flight and closed-session reservations refund on completion or drop, including pending work that outlives a disconnected receiver. It does not expose a raw sender. The existing raw `SessionRegistry` remains a trusted internal compatibility API and is not used for remote delivery.

The shared JSON writer refuses oversized output during serialization. Legacy overflow returns a complete `response_too_large` JSON-RPC error with the original request ID. If even that correlated error does not fit, HTTP 413 is returned before execution. The same authenticated probe is now green: **7511 → 79 payload bytes with a 128-byte limit**. Modern HTTP uses the same bounded writer while retaining its established error status and wire fields. The budget covers the encoded data, not a tool's already-created `serde_json::Value`, allocator overhead, kernel buffers or a strict RSS ceiling; fixed small transport diagnostics also have their documented floor.

Control schema 6 adds an authorization generation maintained transactionally for policy, grant and scope changes, independent of policy epoch. Job/operation updates do not invalidate streams. Each result records its generation; token expiry and a narrow generation read are checked between partial writes. Any generation change conservatively closes an older result stream, including unrelated grant changes. Shared Engine lock admission is nonblocking, SQLite execution and lock waiting use the remaining absolute write deadline, and the deadline is rechecked before the next socket write. The helper restores the connection's actual previous `busy_timeout` and clears its private execution callback. Review independently reproduced the old lock-delay bug: a 100 ms deadline still sent private bytes after a 300 ms held guard; the corrected probe timed out at 100.2645 ms and sent zero bytes. This is one observation, not an end-to-end latency SLA. Full stream liveness checks remain in the outer loop and may wait for policy access; revocation cannot recall bytes already accepted by the kernel.

The v5→v6 upgrade has a consistent pre-v6 backup and an atomic transaction. Failure-injection regression confirms rollback, preserved policy data and the backup's existence. Grant changes across connections, single-scope revocation while another scope remains authorized, duplicate/rolled-back mutations and generation overflow all have regression coverage. Stop existing services and hosts before upgrading; migrating a database does not repair already-running old transport code, and mixed-version rolling safety is not claimed. Storage `lib.rs` is now 94 lines, still only declarations and reexports; the counter logic occupies its own file.

## Process evidence interpretation (EV-06 / task 15.13a, 2026-10-03)

This subtask changes lsof result interpretation, not subprocess execution. Normal successful results, including exit 1 with empty stdout, retain partial coverage because system permissions, warnings and PID start identities are unverified. Positive observations remain available and the verdict includes their count; an empty partial result stays unknown. The old empty-request Full result only represents an empty query set and cannot establish that a file or system has no users. Public signatures and result types remain compatible.

The parser reads byte tags and NUL boundaries rather than slicing UTF-8 at byte 1. Invalid tags/PIDs, missing process context and unterminated fields are unobservable. Query keys retain native bytes, but NUL-delimited lsof names are display fields: they can contain backslash, caret or hexadecimal escapes. Without a verified reversible protocol, fields with potential escapes, control/non-ASCII bytes or a deleted annotation are not matched; other unambiguous ASCII positive observations remain. Unicode, non-UTF-8 and marked/escaped names have unknown identity, not declared tool support. Windows requests that cannot be represented losslessly are explicitly unobservable; a native Windows lsof provider is not claimed. This is path observation, not opened-file identity verification. ## Shared evidence runner (EC-04 / task 15.13b, 2026-10-03)
