# 实际平台末段请求失败与有界准入修复

对应 RE-07 持续 HTTP 验收及原 25ms 发起节奏；完整任务仍未完成。

## 当前原生证据

CI 37776446882 / d8d3995f 的 Windows 安装包失败发生于 HTTP 阶段，正式 20k/200k 未到达。已完成 2336 次查询，末请求开始只剩 3.3089ms，8.2219ms 后得到 TimeoutError，总观测 60.0048674s。macOS Intel 安装包同阶段失败：1386 次完成，剩 28.060076ms，30.244379ms 后超时，总观测 60.002127897s。两者保留原错误及数值时序，未观察到 429，不能将此失败称为服务限流。

macOS Intel 源码 job 的 stdio 验收为 17/18，仅 explain 为 false；原报告丢弃实际 RPC 错误，因此不能据 false 断言是授权窗口、缺实体或其他原因。后续未执行的 expiry 步骤缺文件又导致附属上传失败，不是第二个已复现的产品缺陷。

## 修复与验收边界

HTTP 保持原 40 次/秒上限和完整 60 秒观测。每次发起前（包括 token 准备后）检查剩余额度至少为 max(25ms, 本轮已完成请求最大耗时)。剩余不足时观测至原截止时间，不发起一个已经缺少已知完成成本的新请求；报告新增 dispatch_reserve_ms。已发请求仍有 min(10s, 原剩余时间) 等待限制，任何网络/HTTP/业务错误原样失败，不捕获超时当作完成、不续时或重试。最大观测成本不保证未来请求不会变慢；未来请求若超时，验收仍失败。

stdio 失败报告新增允许列表业务码、RPC 错误码与结构化成功布尔值；禁止输出路径、主体、错误正文或工具参数。实际 debug 子进程显式启用既有授权阶段诊断，报告只保留固定 5 种标签、有限数值及最后 32 条；release 不会开启该编译期诊断。此处补足定位证据，不能称 explain 问题已修复。响应同时包含 result 和 error 时仍拒绝验收成功。

测试先复现末段 3.3ms 仍发起、token 消耗后仍发起、28ms 不足已观测 40ms 成本仍发起三种行为失败。最终 HTTP 目标 18/18、stdio 诊断 4/4、完整脚本 327 项中 326 通过/1 项 Windows 原生 Job 测试本机跳过，包组成 11/11，OpenSpec strict 和 diff 检查通过。初始部分临时红灯日志已不可用，归档时从 Git d8d3995f 原代码在隔离模块中重现这三项行为失败及四项诊断能力缺失，未改工作区源码。测试时钟与错误分类通过不代替真实 MCP 新候选原生验收；新代码尚待同 SHA CI。

## Windows 容量与性能仍未达标

同 runner 20k 对称 1/2/4/4/2/1 诊断造数据为 8.112/7.822/9.211/9.595/7.706/7.594s；当前证据不支持把单线程称为所有 Windows 规模下更快。不得以更小文件数、硬链接替代、跳过清理或放宽 300 秒来关闭门禁。原 zip 与回执在 docs/benchmarks/windows_load_d8d3995f_2026_10_08；HTTP/stdin 原始失败日志和源码指纹在 docs/benchmarks/http_dispatch_admission_2026_10_08。
