# 当前 Store release 查询与空间测量

源码基线 `8d50cfb7b089467d8d2f661cfb373066e75ec626`；314 个 Store/Core/manifest 输入逐字节核对。两平台都执行同一真实 release 测试，不使用 Debug 数字。macOS ARM64 Rust1.98.1；Linux ARM64 Docker Rust1.97.1，镜像 digest 和当前源输入、产物、原始日志见 `docs/benchmarks/store_release_8d50cfb_2026_10_08/receipt.json`。

这是合成不可变元数据夹具。旧侧是同夹具 v8 的 COUNT/SUM SQL，新侧是迁移后聚合 API；不称为两个产品提交或完整 CLI/MCP 的性能对比。

每个查询序列100次；分页分别实际解码10与100节点，测试逐次断言相应读预算，目录与tree子页均覆盖。总节点扩大10倍没有扩大解码页面。没有测量SQLite物理页读取量；热缓存计时排除建立连接，不能推广为冷启动、鉴权、传输或端到端延迟。

实际进程峰值RSS：macOS 83,066,880字节（79.2MiB），Linux 77,537,280字节（73.9MiB）。各值包含同一进程的20k和200k两夹具，排除编译器，不是每页或单一夹具峰值，不承诺严格内存上限。Linux由独立父进程实际wait后取得子进程rusage，不用Docker客户端的宿主RSS替代。

200k迁移（含一致性备份）约macOS654ms/Linux530ms；fenced发布（含采样、验证、提交和checkpoint）约macOS2050ms/Linux1980ms。采样发布峰值WAL两侧均182,907,432字节，须计入容量规划。1ms采样不是空间严格上界，原数据和backup/WAL/temp完整指标保存在JSON。

验收状态：本轮两个测量测试均1/0；只能确认上述Store子项。原200k真实文件系统配对扫描失败、深目录、实际CLI/MCP端到端负载、Windows/macOS Intel、同SHA三平台CI及监督产品链继续开放。不能用此元数据基准替换原扫描门禁，也不勾选总体生产验收任务。
