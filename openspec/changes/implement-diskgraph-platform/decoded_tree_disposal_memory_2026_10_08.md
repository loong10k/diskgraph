# 协议树迭代销毁的存储成本

延续 PF-06 和扫描转换内存优化。当前 `DecodedTree` 为非递归销毁按完整节点数预留 `Vec<Node>`，销毁时把每层 children 整批搬入工作区。宽目录因此会触及另一份完整节点存储；这是真实额外成本，但未证明它是现有配对 RSS 差异的唯一根因。

本轮将清理工作区改为持有原 children 缓冲区的拥有型迭代器，按深度遍历，不复制整层 Node。须保留：

- 准备阶段可失败分配，进入销毁后不再分配；成功、部分组装失败、取消及 panic 都由原 owner 迭代清理。
- 不提供逃逸成裸 Node 的公开接口；仍不依赖递归 Drop，不把协议完成当 OS 退出。
- 按已验证节点总数预留帧空间，最多八个机器字/节点；此为清理工作区存储门禁，不是整个协议树、进程 RSS 或严格扫描内存上限。
- 原 pinned Node 内容、顺序、协议、扫描选项与 vendored pin/源码/摘要保持。

验证须包括预留存储红/绿灯、实际 pinned 扫描 roundtrip、深树小栈成功与错误释放、组装中取消/panic，以及有界分配门禁。当前 native CI 仍运行，只做本地候选，不立即推送取消它；后续须对应候选 SHA 重新完成配对性能及原生验收，不能据工作区节省声明 RSS 门禁关闭。

本机验证结果：20k节点工作区实际预留从2,400,000字节降到640,000字节（减少73.3%）；旧实现超过每节点八个机器字门禁时真实失败，新实现通过。此测量只覆盖预留工作区，不能称为RSS下降73.3%。宽20,001节点与深10,000节点原协议树销毁的实际分配次数均为零，深树使用256KiB栈。

scan-worker全部目标124项通过，包含实际pinned扫描roundtrip、深树小栈、取消/panic和部分组装释放；Clippy拒绝警告及fmt通过。vendored摘要与pin回归4/4通过。仍缺该候选的跨平台同SHA验证及配对峰值RSS/扫描性能，不关闭PF-06或全平台就绪任务。
