# 授权观察窗口待决定方案

状态：待用户确认；本文件不修改现行规格或生产预算。

现行 `bounded-queries/spec.md` 要求独立授权 SQL 使用固定 50ms 窗口。原生 Intel 失败分别出现连接打开 89.955ms／线程 CPU 1.139ms，以及归属 SQL 125.493ms／线程 CPU 1.578ms。当前归属 SQL 的隔离 EXPLAIN 使用归属主键和隔离记录主键；没有发现这条查询全表扫描，SQLite 锁等待为零。同轮只缓存编译产物、不缓存结果，编码后仍另开新鲜连接。不能从这些证据推断具体 I/O 或调度原因，也不能靠优化指令保证任意宿主在 50ms 内完成。

待审选择：

1. 保留固定 50ms 和现有正向成功门禁。继续寻找有实测依据的降低耗时方案；当前原生失败保持未解决，不重跑冒充修复，不允许返回未经末段授权的数据。
2. 将终检数据库观察窗口改为默认 250ms；能力回调保持 50ms，整次数据查询期限及额度不续期。授权错误、隔离、撤权与取消仍拒绝结果；独立新鲜连接、零 busy 等待保持。更新对应规格和时间边界回归后，在完整默认调度下做三平台同源码验收。250ms 仍是失败关闭的合作期限，不是硬实时或任意负载下保证成功。

选择 2 改变既定时间契约，须按用户 AGENTS.md 第六节第 4 条确认后才能实施。它也不解决不可回收 I/O 下有限前端退出；独立监督服务部署决策保持单独待定。
