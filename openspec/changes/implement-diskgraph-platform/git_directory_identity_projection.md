# Windows Git 目录身份复用

目录版本捕获在 `WindowsFileState::capture` 已成功读取完整 FileIdInfo 后，再向同一借用句柄查询一次 FileIdInfo。优化使用本次捕获的完整卷号、128 位 ID 与创建时间，不从旧的 64 位兼容身份推导，不缓存跨操作结果，不更改每次父链重新打开、独立版本复核或原请求期限。

验收：只接受通过原目录安全验证的状态；高 64 位身份不同必须不匹配；持久目录身份匹配仍要求创建时间；重解析、占位、待删除和非目录状态仍拒绝。用合成完整原生字段覆盖高位和错误状态，用真实 Windows 目录核对原捕获与版本投影。捕获后的纯状态构造不接收文件句柄，不能再次执行文件查询。

新增状态构造 API 的缺失编译是开发 RED，不作为已复现的生产行为缺陷。原生定向结果、默认并发完整结果与 release 性能分别记录；静态少一次查询不等于 15 秒完整 Git 采样或 Windows 200k/300 秒全流程通过。整体生产门禁保持开放。

Windows Rust 1.99 原生执行：缺失 API 实际产生三处 E0599；包装器匹配旧编译器诊断措辞而额外触发 AssertionError，该错误同样保留，不作为生产行为 RED。实现后投影 3/3、既有原生状态 4/4 通过；Clippy 先拒绝测试夹具的 Default 后字段赋值，修正初始化后投影 3/3、格式及 all-target Clippy 通过。源码与日志摘要：`docs/benchmarks/windows_git_directory_identity_16d1_2026_10_09.json`。没有 release 或全负载性能收益数字，完整默认并发仍待复验。
