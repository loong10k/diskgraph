# 持续HTTP读取验收增量（未完成原生验收）

沿用release-evaluation的RE-04/07，新增显式`--soak-seconds`参数；默认0保持既有短验收。实际执行时复用同一个MCP进程及CLI创建的隔离数据库，在固定总期限内重复查询，每次核验HTTP状态、实际scope和非空结果。最多保留最后4096次延迟，响应最大1MiB，失败不输出成功报告。单次网络等待不超过10秒及开始请求时的剩余期限；urllib同步网络操作不是硬实时抢占，不承诺严格退出时刻。

持续阶段结束后为同一主体重新签发有效token，再执行原有数据库实时撤权拒绝，避免把token到期当作撤权通过；后续legacy SSE及原进程退出检查继续执行。

红灯：新增4个测试在实现缺失时失败。绿灯：持续阶段6项（固定期限、归属/业务失败、原异常传播、参数边界、响应上限和5000次请求的有限样本）；加原HTTP退出测试共9项通过。脚本全量304项：303通过、1项本机不支持的Windows原生Job测试跳过。测试时钟和HTTP响应替身仅证明夹具逻辑，未运行真实MCP持续阶段。

在已满足既有受保护扫描worker部署条件的原生验收环境中，可使用同一构建的实际CLI/MCP运行：

```sh
DISKGRAPH_ACCEPT_BIN_DIR=/absolute/path/to/binaries python3 scripts/accept-readonly-http.py --soak-seconds 900
```

该命令执行真正的索引及授权数据库夹具，不修改用户数据库。必须另外绑定源码SHA、二进制摘要和实际平台保存运行输出。尚未接入当前正在运行的CI；不为此重启已有完整矩阵。既有包负载300秒门禁不变。

未完成：真实各平台持续运行、并发长期稳定性、RSS采样和增长判定、SSE反复连接/撤权/退休的长期验证。此增量不关闭任何整体生产就绪任务。
